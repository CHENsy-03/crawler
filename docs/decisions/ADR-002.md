# ADR-002：DuckDB 只负责分析，不做事务数据库

**适用范围：** workspace/crawler（信息采集平台）

**状态：** 已采纳

**日期：** 2026-06

## 背景

项目中需要存储采集数据，涉及事务写入和分析查询两种场景。

## 决策

| 数据库 | 职责 |
|---|---|
| DuckDB | 分析查询 / OLAP / 批量导入 |
| PostgreSQL / MySQL | 事务写入 / OLTP / 实时写入 |

DuckDB 不处理：
- 实时写入
- 并发事务
- 数据唯一性约束

## 理由

- DuckDB 列式存储擅长分析聚合，不适合单行写入
- 事务数据库行式存储适合高频写入
- 职责分离后可各自优化

## 影响

- 数据先写入事务库，再批量同步到 DuckDB
- 分析查询走 DuckDB，不影响事务库性能
- 公共查询接口统一屏蔽底层数据库差异
