# ADR-001：Python + Go 双语言架构

**适用范围：** workspace/crawler（信息采集平台）

**状态：** 已采纳

**日期：** 2026-06

## 背景

需要设计一个可长期演进的信息采集平台。

## 决策

采用 Python + Go 双语言架构：

| 语言 | 负责 |
|---|---|
| Python | 页面获取 / HTML 解析 / 文本清洗 / 去重 / AI 分析 |
| Go | API / 调度 / 配置 / 并发 / 权限 / 数据持久化 |

## 理由

- Python 生态适合数据处理和 AI 集成
- Go 适合高并发服务和系统管理
- 职责清晰，避免单一语言瓶颈

## 影响

- 需要维护两套开发环境
- 模块间通过 API 通信
- 公共能力唯一实现，不重复


## 不采用的方案

### 全 Python

- Python GIL 限制并发能力
- 不适合长期运行的后台服务
- 部署和运维成本高

### 全 Go

- Go 生态缺乏成熟的 AI/ML 库
- HTML 解析和文本清洗开发效率低
- 不适合快速原型和数据分析
